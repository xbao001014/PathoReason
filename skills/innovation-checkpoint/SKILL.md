# 创新阶段复盘

用于候选形成后、训练终态回执后、连续尝试没有新增判别信息、目标阻塞或上下文恢复时。只检查当前相关项，给出短的证据与行动摘要，不逐条输出内心推理，也不把清单变成用户必须逐项批准的流程。

这是 Agent 侧的里程碑指导。当前文件不注册定时器、hook 或目标回调；不能承诺每小时自动加载。若平台未来提供可信定时事件，才按事件调用。当前接续依赖既有目标机制与训练回执，等待期间无需维持活跃模型回合。

## 先恢复权威状态

从当前可信任务上下文及工具回执读取目标/节点、用户选择、task_id、候选和计划修订、run/attempt、两个预算体系的已用与剩余额度。读取必要原始文件，不依据压缩摘要补造批准、漏掉失败或重置消耗。仅检查仍存在的阻塞；旧权限错误与当前有效权限分开处理。

## 四项检查

解释异常结果或数据/实现瓶颈时，先按 [执行证据核验](../training-execution/references/execution-evidence.md) 区分源码能力、启动配置、任务运行观察、存储输入与上游处理。使用公共 training audit 获取冻结引用；不要以 request.json 缺字段或源码存在某分支直接断言生效。同一预处理下的可比结果，不等于排除了方法与预处理的交互。核对人/切片、划分、特征版本和统计分母后，再提出因果假设及下一步。

| 检查 | 需要核对的证据 | 导向的动作 |
|---|---|---|
| 科学方向 | 当前改动对应什么假设？是否只剩学习率/种子扫描？文献最接近方法与实质差异是否查证？ | 有判别价值则继续；已证伪或没有增量信息则收敛/换候选。常规优化保留其真实类别，不包装创新。 |
| 实验完整性 | 冻结比较是否一致？哪些单元完成、失败或未知？机制读数是否支持解释？测试是否影响了新的选择？ | 缺证据先补读；修复可重复工程故障；报告负结果和偏倚；科学范围变化交用户取舍。 |
| 运行与资源 | 当前真实回执、日志更新时间、最近 epoch、失败原因、实际消耗和剩余预算是什么？ | 活跃训练正常则等待；可修复故障按同范围流程修复；未知派发先核对；成本不符时提出具体调整，不自行加额。 |
| 策略与交接 | 下一个动作预计减少什么不确定性？是否保留最好可比结果、失败分支和原始输出？ | 在范围内推进最高信息价值的动作；无有价值动作或已达验收则结束；只有关键选择才询问用户。 |

不要为避免“保守”而强制运行所有高风险候选，也不要因工程失败就认定机制无效。探索与确认可以交替，但不能修改既定评价口径追逐分数。有效数据不足时允许结论为不可判定。

## 记录与继续

进入下一实验阶段前，核对该阶段实际会用到的方法来源、实现一致性和成本估算依据；有缺口则接续 innovation-experiments 的 [方法核验](../innovation-experiments/references/method-and-cost.md)，由 Agent 在新修订中处理。复盘不能把旧的接口检查升级成方法/科学验证，也不自动批准后续阶段的训练预算。

在任务允许的输出区追加有版本的简短复盘材料，按需用 study_io 发布以便后续恢复。记录：触发原因/观察时刻、真实引用、相比上一节点新增的事实、当前解释及不确定性、两类预算、下一动作/负责人/完成判据，以及需要用户取舍的具体问题。使用现有目标/checkpoint 接口更新推进状态；普通 Markdown 不能直接改变运行、预算或科学审核状态。

- **可自主继续**：沿既有目标处理下一项准备、读取或同范围修复；不要求用户重复“继续”。需要方案重构时回到 [baseline-innovation](../baseline-innovation/SKILL.md)，需执行准备时使用 [innovation-experiments](../innovation-experiments/SKILL.md)。
- **正在运行**：按 [training-execution](../training-execution/SKILL.md) 留下绑定真实 run_id 的 waiting checkpoint，结束模型回合等待事件。
- **需要取舍**：说明当前节点与差异，通常给推荐方案及一两个替代项，接受自然语言短答；不以推荐替代授权。
- **阻塞/额度不足**：写清责任层、已核对证据、具体解除动作及可继续完成的独立准备；不把所有问题归为权限，也不空转等待。
- **已完成**：对应目标验收给证据和限制；候选无效可完成实验任务，科学审核仍保留原状态。

这份复盘是行动依据，不是自动批准器。所有工程/原生/模型行为/科学结论分层表述。
