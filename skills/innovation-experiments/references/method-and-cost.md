# 方法核验与成本依据

适用于引入或改写损失、聚合、采样、预测解码等机制，以及为新矩阵估算成本。只核验本阶段会使用的机制；不因后续候选尚有疑点中断无关的已授权运行。

## 从来源到实现

阅读原论文的相关公式/算法与官方实现的具体源码文件，记录 URL、访问时间、版本或 commit、公式/函数定位以及本地实现位置。仓库首页、摘要、引用列表和记忆中的方法名称不构成实现核验；来源无法访问时明确缺口，不能声明已忠实复现。

按实际方法逐项对应输入与标签定义、样本子集/掩码、归一化及损失归约、参数共享或约束、预测解码。说明本任务有意改变的部分；变体使用准确名称，不沿用一个实际上不符合的方法名。

构造少量有判别力的纯合成反例或手算样例：选择会使目标方法与邻近替代方法产生不同结果的输入，比较预期损失、解码和必要梯度。测试预期应从原始定义或独立参考实现导出，不复制被测代码作为 oracle。工程接口检查与方法一致性核验分开保存；两者都不能证明科学有效性。

比较改动与基线时核对初始化、层宽/参数量、优化器、调度、采样、特征处理和选择规则。保持固定项一致；因机制必需而改变容量或成本时明确记录，按主要替代解释设置匹配对照。不要将一次多因素变化的收益归因于单一机制。

## 成本估算

已有公共执行回执时，调用仓库 `scripts/training_cost_summary.py --project <当前 project_id>`（使用平台 `.venv/bin/python`）。这是只读汇总工具，不启动任务；按实验、阶段及除 seed 外的完整参数分组，给出完整回执列表和统计。读取相关组的全部样本；不要把早停组与完整 epoch 组混合，也不要用总耗时减去少数抽样评估的外推值来声称实测 fit 均值。若输出较长，保存到任务输出区后按实验/组读取。

优先读取同环境、同阶段、相近模型/数据规模的真实 attempt 回执。列出引用、样本数、完成单元的均值/中位数与范围，说明失败尝试和早停是否计入。训练 fit、评估 evaluate 和失败开销分别估计；混合不同阶段的平均耗时不能直接称为单次训练成本。

将实际消耗、预测区间和拟申请上限分开。已测数据不足时保留不确定性，用有解释的范围/裕量，不能写成精确实测值。累计墙钟、GPU 秒、单元超时、尝试数分别核算，不改既有已用量；预算具体数值仍由用户决定。

汇总工具加 `--format table` 可先看带模型/参数和 group_id 的紧凑表格，默认 JSON 保存全部参数及回执。引用时保留实验与组的对应关系，不能根据数组位置或预想顺序重新贴模型名称；从完整 epoch 的相近配置估计后续完整训练，记录所选组和不确定性。

## 发现不一致时

保留旧实现、方案、原始输出和失败证据，由研究 Agent 在新修订中修正并重新核验。没有影响的已授权运行继续；会影响在跑实验解释的问题应明确反馈其范围，走现有停止/修订机制，不直接改运行中的快照。未解决的方法一致性问题不进入相关新阶段的训练准备结论。
