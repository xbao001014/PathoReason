# 创新输入与工作台成果

## 最小上下文包

| 输入 | 从哪里取 | 用途与缺失处理 |
|---|---|---|
| 研究目标、已选基线、允许范围 | 当前用户意图、持久目标、已登记方案 | 短句继承最近明确选择；存在实质分岔才澄清。 |
| 任务与数据协议 | 当前 task_id、冻结 TaskSpec/划分/特征清单/指标与测试暴露记录 | 保留患者或主体分组、数据谱系、选择规则；不默认有空间信息或独立测试。 |
| 基线实现 | 源码 snapshot/revision、环境、模型原始论文/官方代码 | 定位真正运行的机制，区分同名不同实现。 |
| 实验事实 | 训练 inspect、原始日志/指标/预测及已发布报告 | 核对计划绑定、所有种子/折、失败、成本；报告摘要与原始数据矛盾时保留差异。 |
| 既有探索 | 历次 proposal、负结果、修复历史、人工干预 | 避免重复探索，保留未解决替代解释。 |
| 文献与边界 | 原始论文、官方仓库、检索日期和访问范围 | 记录支持/反例及最相近方法；摘要可支持的结论不能超出实际读取范围。 |
| 资源与权限 | 当前原生工具权限、Agent 预算、实验独立预算与有效批准 | 工具 allow 不等于科学批准；基线预算不自动覆盖新实验。 |

正式提示词可能只附成果摘录：当前实现每份文本最多约 6000 字符、合计约 18000 字符，且部分文件不附正文。这是实现细节而非完整上下文保证；发现省略时按真实 artifact 引用读取原文。不要大范围把所有历史文件灌入上下文；优先索引与当前假设有关的段落、指标及回执。

## 候选卡片字段

用 `pathoreason.innovation-proposal/1`，当前严格 Schema 不允许额外顶层字段。以下是字段映射，不是真实研究成果，也不要原样发布占位值。

| 字段 | 应填写的内容 |
|---|---|
| proposal_id / task_id / revision | 稳定候选 ID、从工具获得的真实任务 ID、此次新修订；不要发明任务身份。 |
| title / hypothesis | 具体机制名称；可证伪的 X → Z → Y 假设。 |
| baseline / selection_reason | 已选基线及实现引用；验证质量/稳定性/成本依据、已知测试选择偏倚。 |
| gap / mechanism | 观测事实与尚未证实解释分开；机制如何针对局限，类别是常规改进、已知适配还是新假设。 |
| falsification | 哪种结果反对机制，哪些情况只能说明证据不足，如何区分替代解释。 |
| implementation | 改动位置、数据前提、成本估计及未知数；完整计划另存引用。 |
| source_refs / evidence_artifact_ids | 已核验论文/官方源码地址；本项目真实已发布成果 ID。 |
| parent_proposal_ids | 真实派生关系，没有则为空。 |
| conditions | 每项用 title、question、criterion 描述基线/改动/消融的判别条件。 |
| decision | proposed/selected/deferred/rejected；仅报告已有决策，文件声明不赋予平台执行权限。 |

完整协议冻结、上下文索引、检索记录及预算估算放单独版本化说明，随后以其真实 artifact ID 引用；不要给 schema 增加自创字段。通过 scripts/study_io.py publish 的当前帮助与允许路径发布新成果，读回回执。需要阶段归类时发布 workbench-manifest/1，把成果关联到 innovation 或 innovation_runs；没有发布的工作区文件不会自动成为工作台候选。

保留同一候选所有修订、被拒或无效方案、失败回执及历史报告。候选卡、实验报告与科学审核是不同对象；文字 selected/complete/pass 不可替代对应门禁。
