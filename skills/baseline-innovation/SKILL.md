# 从优质基线提出创新

目标是在当前任务中结果较好、证据可核验的基线上提出可检验的机制变化。保留用户已选模型；未选时根据验证集主指标、跨种子稳定性、计算成本和适配条件推荐主基线，必要时保留一个互补参照。不要因开始创新而重做整套模型选型，也不要把某个项目的模型或病种写成默认答案。

## 恢复研究起点

先读 [上下文与成果协议](references/context-and-output.md)，形成简短的证据索引：用户目标与已选基线 → 冻结任务/协议/代码 → 已完成训练与原始结果 → 已有候选和失败 → 可用预算与当前授权。缺失的信息标为未知，摘要不等于完整证据。

- 以训练/验证证据诊断、选择和迭代。测试指标不用于新一轮自适应选模型、阈值、种子或机制；既有报告已经曝光的测试信息仍保留来源和限制。如果当前基线曾由测试成绩选出，明确记录这个选择偏倚，不能将其包装成未曝光选择。
- 主指标未约定且会改变选择时，结合任务给出简洁选项；已有明确选择直接沿用。可补齐的日志、方案和文件由 Agent 自行读取，不把路径、Git SHA 或完整指令交给用户补写。
- 将“观测事实”“机制解释”“缺少的判别证据”分开。总损失上升、单次低分或类别偏置只能支持诊断线索，不能单独证明过拟合、梯度失效或某模块造成失败。

## 把证据变成候选

1. 阅读主基线论文及实际使用的代码修订，定位输入、表征、聚合、目标函数和决策链。核对现有特征是否含坐标、多尺度、临床变量等；不能设计依赖不存在信息的方案而隐去代价。
2. 用可用的 websearch/webfetch 或 paper-lookup 检索原始论文与官方代码。覆盖任务领域的建模假设，以及可能迁移的 ML 机制；同时查相近工作和反例。按需使用 benchmark-design 的公平比较指导，无需重新枚举全部基线。若联网受阻，继续分析本地证据，把未核验文献与新颖性保留为待查，不编引用。
3. 围绕具体局限提出少量互补候选，通常 2–3 个足够。每项写清“改变 X，通过机制 Z，预期在读数 Y 上产生可观察变化”；说明修改位置、适用前提、最接近的已有方法及实质差异。可以提出跨领域机制，但应保持当前任务和基线的可比性；更换整个研究问题属于范围选择。
4. 分开标注：**常规改进/对照**、**已知机制的任务适配**、**待验证的新机制假设**。调学习率、种子、常规正则或换现成模块可以有用，但不据此声称原创。实现复杂度、模型大小和大胆措辞不是新颖性证据。证据不足时允许暂时没有新机制候选，不为凑数制造创新。
5. 为每项设计最小判别实验：基线与改动、必要的替代解释对照、主指标及机制读数、无效/负效/不可判定条件、时间与数据需求。先验证最关键的不确定性，再安排完整公平比较；适度重复用于估计波动，不能挑最佳种子代替比较。按预期信息价值、科学意义和授权成本排序，而非仅按易实现程度或历史测试提升排序。

## 交付并推进

在候选中保留实际检索/读取记录和最接近已有方法的对应关系。未核验原文或官方源码的条目标为待核验，排序可依据验证证据与判别价值，不据此宣布“原创性最高”或已经复现；联网成功本身也不是新颖性证据。实验适配时接续方法一致性核验，不以有限梯度的合成检查代替。

发布候选比较说明和逐项 `pathoreason.innovation-proposal/1`，字段映射见上述协议。引用原始成果及文献，不覆盖旧报告。方案文件标为 selected 不构成执行授权或科学审核。

用户只要求方案时交付到这里。若已授权某方向的实验准备，接续 [innovation-experiments](../innovation-experiments/SKILL.md) 自主适配、检查和准备可审阅计划；若多个实质不同方向尚未选择，推荐一个并仅询问这个取舍。不要要求用户逐次确认冻结、合成检查或常规修复。正式训练仍按公共训练机制确认方案和独立预算。

候选形成、实验回执到达或策略停滞时使用 [innovation-checkpoint](../innovation-checkpoint/SKILL.md)。研究 Skill 不提供后台调度或预算权限。

- 理解原文与本项目差异时读 [来源与适配](references/source-and-adaptation.md)。
- 用户要求验证这些 Skill 的效果时读 [效果验证协议](references/skill-evaluation.md)，不要把本次编写或静态校验当作研究效果。
