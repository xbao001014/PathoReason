# 权限模式简化

2026-11-03，`0.6.20-p5-permission-modes`。用户明确选择：自动批准等于全部工具允许，个别限制使用自定义。此规则取代 0.6.19 中“自动批准仍保留逐项禁止”的新设置语义；历史证据不改写。证据目录：`/data/bxn/PathoReason/acceptance/permission-modes-20261103/`。

## 实现

- 自动批准统一将命令、文件修改、网络、外部目录四项设为 allow；逐次确认统一设为 ask；自定义严格按逐项设置。前端选择预设时立即显示实际值，修改单项自动切换自定义并继承其余实际值。保存才应用，取消不写入；删除冗余的“允许全部工具并自动批准”二次入口。
- 后端也规范化预设，不依赖前端清理旧字段。即使请求携带 `mode=auto,bash=deny`，明确选择的 auto 仍规范化为全部 allow。新保存值及未来冻结配置带 `semantics_version=2`，公开契约快照为 `contracts/p5-permission-modes/` 和对应 OpenAPI。
- 无版本标记的存量配置按旧语义读取：含显式禁止的旧 auto/ask 显示为自定义，逐项实际行为完全保留；无禁止项则保持原模式。仅作读取投影，不迁移或覆盖原数据库行。原生派发、冻结提示和会话读取使用同一兼容入口，历史待派发回合仍按历史冻结权限执行。未知版本拒绝解析。
- 权限保存仍以 CAS 和目标状态更新事务为边界；旧权限阻塞待复核，不自动派发。模式变化但实际动作相同不重写目标。工具允许不扩大研究范围、预算和训练授权；私密凭据规则及 dialogue/inspection 执行范围继续生效。

## 分层验证

工程：86 项定向测试通过，覆盖 243 种旧模式/动作组合、旧记录不回写、明确 auto 保存覆盖旧 deny、旧待派发冻结配置仍拒绝，以及目标恢复/并发/事务边界。完整回归 390 通过、2 跳过（定向与完整有重叠，不相加）；TypeScript/Vite 构建通过。

界面：1440/390/320 宽度的显式夹具验证自定义禁止 → 自动批准全部允许、取消不保存、一次保存写入四项 allow、单项限制自动切换自定义、再选预设统一重设，无 JS 错误或横向溢出。所有写请求被夹具截获；线上只读复核当前四项允许和“权限待复核”入口。

原生：独立临时 OpenCode 会话验证旧 auto+deny 仍全部 deny、新 auto+旧字段全部 allow、自定义混合动作逐项一致，私密文件仍拒绝；无提示词、无消息、无模型调用，检查后删除临时空会话。记录 `native-validation.json`。

模型与科学：本次没有追加模型调用或训练。上一版独立 Flash 的文件写入/命令读回证据见 `PERMISSION_RECOVERY.md`，不充作本次模式切换后的新模型验收。研究方案与科学审核未因此通过。

## 发布与操作

当前原对话已经是 auto+四项 allow，升级读取后仍为自动批准，无需再次保存或重复授权。其他旧混合模式显示为自定义；用户明确选择自动批准并保存后才全部放行。刷新前端即可使用新设计，恢复原准备目标仍走“核对权限并继续”。

保留旧发布及数据库快照供核查，发布包保存源码、构建产物与 SHA。新配置含版本标记，不能直接回退到不理解该字段的旧代码或恢复旧数据库来删除消耗；回退应使用保留兼容读取的修复版本。历史输出、额度、原权限修订和冻结配置不变，未自动恢复研究目标。此次前端构建已包含此前 `2593df8` 的聊天宽度与标题样式，不再依赖附加 CSS。
