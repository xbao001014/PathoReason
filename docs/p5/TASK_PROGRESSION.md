# 方案选定后的自主准备

版本：`0.6.17-p5-task-progression`；dialogue MCP `0.3.0`；benchmark-design `0.5.0`。

## 观察到的问题与责任层

原研究在“选择方案→起草→固化”间反复等待用户。公共 guidance 将 clarify 选项限定为“只记录方向”，还提示再次提供下一步；目标控制器不区分必要取舍与常规 next_step，任意 offer 都会覆盖当前目标完成/接续状态。自由输入选项原文不会被记录为选择，和点击行为不同。原准备回复还错误地把重划分后新调用次数为零等同于历史暴露清零，并把修改 compute.json 说成训练授权入口。保留原回复，修复公共控制与指导，不改研究材料。

## 实现

- 新选项 scope=`continue`：仅用于当前持续目标中的关键取舍。选择直接进入原目标后续工作，执行范围继承来源回合；当前权限设置、额度和训练门禁仍独立。只读不会升级为编辑/计算权限，暂停不会被选项隐式恢复。旧 clarify/plan/inspect 语义保留。
- 输入完整选项文本或唯一选项标签等同于点击。唯一提议后的有限常用短确认可绑定；多个选项下的“按你说的来”不代选，临时只对话澄清。独立冻结 goal_execution_scope 保存原任务范围，明确选择后恢复该范围，避免永久困在澄清回合。
- 进行中的目标不能提交机械 next_step 确认。真正新任务的 next_step 须在当前目标完成检查点之后提供；完成回执不再被这样的后续建议覆盖为 waiting_input。必要 clarification 仍保留选择并等待。
- 新可选 GoalBlocker：platform/permission/input/resource 与具体补齐动作。训练能力缺口使用 training_execution，统一读取实际 launch 门禁。平台训练能力未就绪时普通 resume 拒绝，无新回合、不消耗预算；增加额度不解除它。修订目标可改为独立准备工作，保留原阻塞事件。
- 前端显示“按选择继续当前目标”，结构化阻塞自动展开并说明责任；已知训练后端缺口隐藏无效继续按钮，调整/取消仍可用。
- 正式提示词与公共 Skill 将适配、隔离依赖准备、内部合成检查、回执检查和源码冻结定义为准备内部步骤。用户只请求规划时仍止于规划；真实启动绑定具体方案、资源和评价边界，已有同范围“就绪后运行”授权可沿用，不将每个内部检查变成人工审批。
- 历史暴露指引明确区分新运行评价次数和既有病例开发/测试暴露；换 seed、名单或归档名不清除历史，也不自动恢复独立盲测资格。

新字段均向后兼容，旧 payload 可读；历史回合/配置/目标不回写。新契约保存在 `contracts/api-p5-task-progression.openapi.json` 和 `contracts/p5-task-progression/`，旧快照不覆盖。

在确认业务与原生实例均空闲后，维护顺序为：

```bash
.venv/bin/python scripts/service.py stop-app
.venv/bin/python scripts/service.py refresh-native
.venv/bin/python scripts/service.py start
```
