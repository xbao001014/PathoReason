# 整体项目归档与删除

2026-11-04，应用 `0.6.29-p5-project-lifecycle`。用户确认删除项目时默认同时清理项目独占资产，只保留最小删除与预算记录。

## 展示与操作

每个项目行提供 `⋯` 管理入口，支持归档、恢复和删除。沿用「对话 / 已归档」分类，但分类及数量按项目计算，不受搜索词影响：

- 对话：正常项目，以及清理中或失败的项目。
- 已归档：整体归档的项目，或确实存在单独归档对话的正常项目。没有归档内容的正常项目不再占位。
- 整体归档项目在归档分类内显示全部未删除对话；父项目继承只读，不改写各子对话的归档标记。
- 恢复项目回到对话分类，原来单独归档的对话仍归档；归档暂停的自主目标不会自动恢复或调用模型。

删除需输入完整项目名称。默认勾选清理项目独占文件与训练产物，也可明确取消勾选保留文件；清理开始后范围冻结。清理失败保留项目入口、进度与重试，避免伪装成删除成功。当前项目删除后选择剩余正常项目，再退到归档项目；最后一个项目删除后保留新建入口。同步清除对应对话的浏览器草稿和选择缓存，跨窗口事件及低频项目轮询更新列表。

## 服务端与数据边界

新增 `GET /api/v1/research-projects?include_archived=true` 的项目统计/清理状态、`GET /research-projects/{pid}/lifecycle`、`POST /{pid}/archive`、`POST /{pid}/restore`、`DELETE /{pid}` 和 `POST /{pid}/deletion/reconcile`。路径均在 `/api/v1/research-projects` 下。动作校验项目 revision；删除还校验确认布尔值、完整标题和明确的资产范围。

`project_deletions` 是增量旁表；旧项目/对话记录无需迁移。父项目的状态门禁覆盖新对话、发送、单独会话维护、重命名、任务代码修改及成果发布等操作。已删除公共读返回 410，清理未完成返回 409；生命周期回执仍可读。全部项目删除后启动不会重建历史种子项目。

归档和删除先核对全部应用回合、原生会话、上下文操作、权限派发、注册训练与研究任务。运行中及结果待核对时拒绝；不替用户停止研究。项目清理标记先落盘，再复用既有会话原生删除与内容清理，失败或进程中断可继续核对。原生会话共享、派生会话归属不明或引擎状态不可确认时保持阻塞，不扩大删除范围。

默认文件清理范围仅为数据根下 `projects/{pid}`、`studies/{pid}`、`research/{pid}`、`artifacts/{pid}`，以及该项目训练账本登记的当前与历史 `training/runs/{run_id}`。删除前检查目录边界、根/祖先符号链接、挂载点和其他项目登记的共享引用；子目录符号链接只删除链接自身。共享训练环境、外部数据、旧项目来源、验收证据及备份不清理。未登记且位于范围外的文件不会推断归属后删除。

数据库移除研究计划、输入/暴露登记、任务代码快照/检查、成果索引和阶段交接内容。保留项目/对话删除墓碑、回合与时长/token 用量、训练额度及逐次已用时长等最小账目；不保留训练计划、执行命令、文件内容或日志。正式项目的预算分区标记保留，防止删除后将这些回合计入其他项目的全局预算。共享全局配置及其他项目自己的来源记录不受影响。此操作不承诺从数据库空闲页、备份和文件系统快照进行安全擦除。
