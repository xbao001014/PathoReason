# 终审后的图表呈现与格式调整

2026-11-04，版本 `0.6.41-p5-presentation-revisions`。

## 用户场景与行为

终审结束后，在同项目原对话或普通新对话要求调整图表字体、配色、布局、页面留白、期刊格式或输出清晰度，可以直接准备新版本。保留科学内容冻结及已批准原件；复查受影响图件、内容一致性和 PDF 页面后，仅提交新版交付确认，无需重新进行蓝图、初稿或审稿裁定。

数据点、统计量、显著性、坐标/类别/标签含义、结论或实质图注变化属于内容修订，返回科学内容审核并更新交付。含义不明确时，用现有 clarification/continue 选项澄清；讨论、假设、引用或否定请求不触发重开。作者的明确改图要求无需重复转换为内部 reopen 操作。

## 公共实现

- 扩展既有受限修订路由，`revision_kind=presentation,target_gate=delivery` 保留前四个有效批准；`content/scientific` 只撤销科学内容和下游交付。适用于交付期间和终审后，仍绑定当前回合 grant、目标/稿件 revision、当前用户原话或有效作者返工反馈，保持幂等。
- 普通同项目新对话可只读发现已批准稿件/交付材料及修订能力；确定修订意图后才在事务中接续阶段。不会因为创建新对话或讨论就改变门禁，不能接管另一个未完成/暂停目标。原目标、账本及原会话材料保留，新工作沿用项目剩余额度和新会话现有权限。
- 图表呈现修订不改变冻结科学稿。修改图片/表格必须绑定原科学材料及新材料 ID；只在新文件路径生成派生版本，不覆盖原件。排版源包及 PDF 仍绑定原科学包 digest。
- `presentation_audit` 是研究 Agent 对数据、统计、标签/单位含义、结论、图注、引用未变的比较声明，逐一绑定本次提交材料 SHA。平台检查绑定、替换映射和声明完整性，不把该报告当作独立科学证明。发现意义变化/未验证则不能当作纯呈现交付批准；可提交明确 blocked 报告，再按实际范围处理。
- 生成/调整病理示意图仍使用已配置的 Seedream 链路，须实际视觉核对；普通排版及数据图呈现复用原始依据，不新增研究实验。
- 工作台显示当前交付图件，派生图明确标注“展示调整 · 待作者审核/作者已批准”，原科学内容批准不自动授予新图批准。旧图与原交付包保持可追溯。

本次只修改公共代码、运行提示、契约与展示；未改真实稿件或图件，未替作者批准、启动实验或增加额度。没有新增数据表迁移或原生 Skill 缓存刷新要求。
