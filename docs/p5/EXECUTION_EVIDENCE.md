## 真实失败与责任层

最新研究回复已撤回加载器固定抽样的说法，但仍把 request.json 未出现环境变量当作运行配置证据，把存储形状直接归因于导出/入库，并把共同限制推断为相对比较不受影响。平台原来没有公开的历史执行证据入口，未来启动也没有独立的账本配置回执；Skill 缺少证据等级和归因规则。报告原文及更正版本保留。

开发者仅做只读核验：最新 CV 注册的 119 个开发集 HDF5 摘要与登记一致，features 行数 1880–2048，其中 37 个小于 2048。未打开封存测试内容、导入研究加载器、执行训练或评估。此观察证明当前存储表示的范围，不能确定上游变换发生环节，不能证明无限制条件下的排序。证据保存在数据盘 diagnosis-review-20261104，不写回研究材料。

## 公共机制

- `pathoreason_dialogue_training operation=audit`：当前回合 grant + 项目绑定，检查范围允许只读审计；对话范围及过期授权仍拒绝。需要 experiment_id，可指定历史 run_id、unit_id、相对 source_file，audit_offset/audit_limit 分页。不调用 reconcile，不记测试暴露，不执行源码或输入反序列化。
- GET `/api/v2/conversations/{cid}/training/{eid}/audit`：同一只读实现，Cache-Control: no-store，项目归属和参数边界校验。
- 账本 run_queued 锚定原计划与控制器；核对注册环境绑定、原快照源码字节、控制器字节、单元输入清单和依赖回执。环境全目录、输入数据内容不重新读取，返回明确覆盖范围。任务参数与实际生效行为分开。对符号链接、硬链接、特殊文件、过大文档、摘要冲突拒绝；单页有数量和字节边界，下一页游标不跳过单元。
- 后续公共执行器在 subprocess 派发前将 `training-launch-spec/1` 写入 attempt.launch_spec，并记录对应摘要事件。内容是固定环境（不继承父进程环境）、解析后 argv、Python、代码/控制器/输入清单摘要及资源限制。账本不在研究进程可写范围；失败与重试保留原回执。它证明平台准备传入的参数，不证明派发成功或任务导入后未修改配置。
- 历史缺失保持 not_recorded，不回填。账本声明已有回执却丢失或不匹配时拒绝，不能伪装为旧版缺失。旧控制器及冻结配置保持原字节；新字段不要求迁移或重置预算。新增审计字段不改变已有操作的幂等签名。
- training-execution、innovation-checkpoint、results-explanation 连接同一执行证据参考，区分源码能力、计划、启动规格、任务观察、存储表示与上游生产来源。要求队列/划分/特征版本/统计分母对齐，保留共同处理与方法交互的不确定性。修订报告仍由研究 Agent 自行完成，不增加用户逐项冻结流程。

契约保存为 `contracts/api-p5-execution-evidence.openapi.json` 和 `contracts/p5-execution-evidence/`；历史契约保留。未改变界面布局，不补发静态前端。
