# 会话权限设置

用户于 2026-10-30 明确授权修改和部署。增量发布：`0.6.1-p5-permissions`。

正式研究对话输入区新增“权限”按钮，显示当前模式。三个选项为逐次确认、自动批准、自定义；自定义支持 bash、edit、webfetch、external_directory 的 allow/ask/deny。自动批准只把询问变为允许，保留明确禁止项；私有文件读取和未开放工具的禁止规则保留。工具权限不是 OS 沙箱，也不替代训练预算、冻结协议或科学/作者审核。

保存只影响当前对话的后续回合；活动回合或原生待处理操作期间禁止保存。旧会话默认逐次确认，新对话不继承其他会话授权。更新使用 expected_revision，防止两个浏览器窗口互相覆盖。所有修订追加保存在 conversation_permission_settings，回合的不可变 runtime_config 记录 permission_settings、permission_revision；旧回合及旧预算不重写。

每个新回合派发前先同步并读取原生权限。OpenCode 1.18.33 的 PATCH /session/{id} 实际追加规则，适配器检查末尾完整规则组；相同组不重复追加，未确认规则时不发送模型请求。恢复已有已派发回合不重新配置或重放动作。

审批支持 once/always/reject；always 仅在原生请求返回非空 always 范围时开放，页面展示这些匹配规则，回执保存相同范围。未知审批结果仍保留 dispatching，不能重复派发。原生会话的既有同类授权不会因切回逐次确认自动撤销；需要撤销时新建对话，或对相关工具明确设置 deny。原生运行时重启后的 always 授权持久性未在本增量中验证；应用保存的模式与规则会在下一回合重新同步。

依据：[OpenCode 官方权限文档](https://opencode.ai/docs/permissions/)，以及本机安装版本原生 /doc 和真实 create/PATCH/GET 观察。并未将 CLI --auto 启动参数直接加到共享服务器进程。

## 部署与恢复

只在核对应用回合与原生任务空闲后重启 PathoReason 应用，OpenCode 服务保持运行。部署前保存修改文件、旧前端和一致性数据库备份，并检查源文件摘要未被其他窗口修改。数据库备份仅作取证，不能覆盖已有科研记录来回退。发布回执记录前后服务身份和文件摘要。

新增权限表可随回退保留；若用户已选择宽权限或授予 always，回退代码前应先在新版本中配置明确的限制并完成原生核对，或切换到新的受限会话。仅回退前端/后端代码不会自动撤销原生会话授权。
