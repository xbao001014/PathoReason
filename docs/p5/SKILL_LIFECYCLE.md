2026-11-03，版本 0.6.24-p5-skill-lifecycle。

## 失败与责任层

实际研究会话调用 baseline-innovation 得到 not found。源码路径已注册，但 8 个已绑定项目的原生实例缓存均缺少新增的三个创新 Skill。直接读取文件的降级曾成功，不能称为原生加载成功。旧 refresh-native 仅核验固定三个名称，新增文件不会自动进入发布验收。

已有创新阶段路由和三个 Skill 是另一窗口已写、未发布的改动；本次保留原内容、补齐指导并一并纳入发布，不将其记为本次从零编写。

## 公共修复

- 按 OpenCode skills.paths 枚举全部 SKILL.md，发现重名、非法元数据和缺失目录时明确失败。当前目录 21 项，不硬编码某个项目或 Skill 名单。
- check-native 可在线只读检查所有已绑定目录的名称、来源路径及真实缓存正文，保存每项源文件 SHA 和缺失/正文/路径差异；失败返回非零。
- refresh-native 仍仅在应用离线、回合/压缩无未决状态、原生无活动会话/待审批时刷新，先检查所有实例，再逐项复查。每项保留刷新前后回执，半途失败不假报整体成功。
- 离线期间允许目标等待独立训练控制器的真实回执；不允许活动目标或合成任务等待。原生实例刷新不停止训练控制器、不删除 session/history，也不改变授权或预算；应用恢复后沿原回执接续。
- 三个创新 Skill 接入产品目录及阶段路由。内部方法核验区分论文/官方实现、合成方法反例、接口检查与科学验证；估算分别使用 fit/evaluate/失败耗时。核验与修订由研究 Agent 完成，不新增逐项用户确认。

## 维护入口

在仓库运行 `.venv/bin/python scripts/service.py check-native` 可只读复核。Skill 发布时，先检查活动回合/目标；在安全维护窗口 `stop-app` → `refresh-native` → `start` → `check-native`。refresh-native 必须覆盖当前配置目录，不以 MCP 重连替代 Skill 缓存刷新。失败时保留 receipt 并核对，不重置会话/额度。

这是一套发布与核验机制；不在每个模型回合在线 dispose 原生实例，也不安装新定时器。新增 Skill 源码需经过上述发布步骤，不能把文件落盘等同于全部旧会话已更新。

## 定向行为验证后的补充

第一轮真实 Agent 读取了新增方法核验指导，检索论文/官方代码，独立修正研究任务中的条件子集损失与累乘解码，并完成判别性合成检查。初次测试脚本错位失败和官方网址 404 均保留。这个回合仍将旧的 Skill not-found 记为当前状态，且成本估算混合早停与完整训练。

因此公共路由补充：当轮先尝试原生 skill 工具；旧错误不能代表现在不可用；直接读取明确记为文件降级。新增只读 `scripts/training_cost_summary.py --project ...`，从公开进度 API 汇总全量回执，按实验、阶段、除 seed 外全部参数及依赖训练参数分组，分别提供样本数/未知数/均值/中位数/范围与失败记录，不修改账本、不估计 GPU 单元计费、不自动授权预算。科研方案仍由 Agent 根据相关组自行估计。

维护前后 OpenCode 进程未重启，研究文件和实验/预算记录核对不变。三宽度浏览器可选择三项新 Skill，零写请求和 JS 异常。原生 8 个目录 × 21 项来源/正文核验通过。工程首轮 69 项、最终原生/目录 18 项、成本补充 10 项通过（有重叠，不相加）；训练/目标回归 40 项通过、1 项环境条件跳过，另一项因隔离工作树缺本地配置失败，补齐隔离配置后单独重验通过。新增测试首次 shell 传输引号错误及发布脚本 health 路径误用 404 也保留；真实 `/health` 正常，仅一次发布重启，未据 404 再次重启服务。
