# 长对话交互与慢链路性能

2026-11-04 用户反馈前端交互比此前慢。

## 证据

服务器首页／项目列表约 4ms，本机转发同类请求 2–5s，拥堵时健康检查达到 14.8s。Tailscale ping 明确经 DERP(sfo) 中继，未建立直连；ICMP 往返 238–443ms，中继探测 562–731ms。服务器负载与可用内存正常。对话响应约 361KB、训练方案约 732KB，原页面每 4 秒全量读取，慢链路下可叠加。

80 轮合成对话、每轮 Markdown 表格和 8 个工具的同条件浏览器测试：输入到双帧更新平均 297ms → 68ms，最大 492ms → 102ms；测试输入期间 >50ms 长任务由 13 次降为 0。延迟 1.2s 的请求配合突发事件，最大并发 7 → 1，请求数 8 → 2，最终变更保持可见。数字是本机测试结果，不保证所有设备相同。

## 改动

- Markdown 以正文和稳定成果回调记忆化；执行过程组件记忆化。轮询相同结果保留状态，部分变化复用未变化回合，减少无关输入触发的解析与绘制。
- 对话与训练刷新串行化：定时器不积压，事件或操作在请求期间发生时合并为后续一次新读取。错误可在下一次刷新恢复；切换会话保持代次及 ID 校验。
- 活跃对话或推送未连接仍每 4 秒检查；推送正常的空闲对话约 30–32 秒兜底刷新。消息事件仍即时触发。后台页暂停对话／训练轮询，回到前台立即核对。
- 已全部完成／取消的训练列表约 30–32 秒兜底读取；空列表、草案、活跃和待处理状态仍每 4 秒检查。原授权、版本冲突及输入保持规则不变。
- 连接状态继续每 10 秒更新，模型和 Skill 目录在初始化及显式设置刷新时读取，避免同一目录持续下载。
- 本机 `pathoreason-tunnel.service` 启用 SSH 压缩，保留自动重连。压缩减少传输量，不消除中继往返延迟。
