# 子对话重命名与首轮命名

2026-11-02：按用户在子对话中的要求实现。代码和隔离验证完成；该子对话未发布线上静态资源、未重启应用或 OpenCode，供主线程统一集成发布，避免打断正在进行的运行时调试。

## 操作与行为

子对话右侧 `⋯` → 管理会话 → 重命名，支持 Enter 保存、Esc 取消及 1–120 字符名称。运行中的对话和已归档对话均可重命名；删除中或已删除的对话拒绝操作。保存立即刷新列表，其他窗口沿用列表轮询更新。并发编辑使用名称 revision CAS；冲突保留输入，用户重新读取后再保存。

新增对话首轮成功结束后自动命名一次。同一模型回合在最终回复末尾提供独立 `<pathoreason_title>` 元数据行，总结用户主题，不另开模型回合、不调用额外模型。平台将该元数据与正文分离，流式未完成标签不在界面闪现；原生消息保留原始输出。自动名称最多 80 字符。未提供有效元数据时，仅用首条请求的短主题摘录回退，不追加推理或扩大额度。

手动改过的名称优先，包括首轮前保存相同名称及首轮运行期间改名；自动结果不会覆盖。失败或中断的首轮保留原名。已有历史回合的对话不回填命名。应用崩溃发生在首轮完成与名称写入之间时，可从已保存的候选恢复且只应用一次。

## 数据与边界

`GET/PUT /api/v1/conversations/{cid}/title` 提供名称和独立修订；`conversation_titles` 旁表保存首轮绑定、来源、候选与处理状态。首轮绑定和回合创建同事务。修改只更新产品会话名称，不修改目标、冻结配置、会话原生标识、研究材料和预算。删除会话同时清除此旁表，不保留名称文本在删除后的在线记录中。

新契约快照为 `contracts/api-p5-conversation-titles.openapi.json` 与 `contracts/p5-conversation-titles/`，旧 API 快照保留。适用于两类运行时的公共服务；本次未启动服务器 Codex，也未进行真实模型调用。原生引擎内的会话名称不作异步同步，产品会话名称为界面权威来源。
