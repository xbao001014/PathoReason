# 任务选项范围与检查点阻塞恢复

2026-11-03，版本 `0.6.26-p5-goal-scope`。

## 真实失败与责任层

用户选择保存阶段汇总且不新增训练，Agent 将选项标为 `clarify`。该选项冻结为 dialogue 范围，独立工具权限虽为 auto/allow，范围限制仍拒绝文件操作。输出上限从 8192 调到 32768 后两轮正常 stop，但文件检查点被 `goal_outside_turn_scope` 拒绝，控制器仅看到未保存检查点，重复一次后显示 `goal_no_progress`。原生目标绑定没有丢失，科学结论与汇总文字正确性不由这次系统修复背书。

## 公共机制

- 未完成活跃目标的选项不得使用仅方向讨论的 clarify。发布阶段返回稳定错误 `guidance_goal_scope_conflict` 和可修正说明；让 Agent 改为继承原范围的 continue 或只读 inspect，不在服务端猜测语义或悄悄提权。独立方向讨论、目标完成后的新提议保持兼容。保存、登记、固化成果属于工作，“不新增训练”不等于“禁止文件操作”。
- 当前有效回合被拒绝的范围检查点写入独立 `goal_checkpoint_rejections`：仅错误码、回合、revision 与时间；不保存 grant、未核验成果或冒充成功检查点。无效 grant、过期回合/revision 不得写入。Agent 可在同一回合纠正；有效检查点优先，原拒绝记录保留。
- 没有纠正的范围错误在本轮结束后直接 blocked，不再消耗第二轮；纯对话范围无检查点也停止，明确提示范围原因。MCP 错误解释作用域而非目标脱绑定，允许提交不含越界证据的真实阻塞检查点。有效澄清仍等待用户选择。
- 已有历史目标只读追溯“选中 clarify 的用户回合 → 同一目标原始来源回合 → 自动后继”，核对冻结配置摘要。可恢复范围只来自该原始回合的 standard/inspection；含糊接受多个选项、不同目标、无来源记录不提供提权入口。上下文恢复优先。
- 前端同一进度栏显示范围原因与“按原任务范围继续”/“按原只读范围继续”。用户点击后带 revision 与明确 resume_scope；服务端重新核对来源和额度，记录用户控制事件，只改变下一回合范围。旧失败、旧冻结配置、已用回合、32K/high 等请求设置不改，当前显式 deny 仍生效。训练授权、计算预算、数据与科学门禁独立保留。
- 普通恢复不能无声跳过可见范围选择；并发/旧 revision 请求被拒绝，前端同步防重入。自然语言明确工作仍走正常用户提交并保留原目标/已用额度，不要求使用技术字段。
- 校正公共提示中“尚无训练后端”的过期断言，改为检查当前执行器就绪状态。
