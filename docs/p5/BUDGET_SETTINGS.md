# 对话额度设置

版本 `0.6.15-p5-budget-settings`。正式研究对话的输入框设置栏新增“额度”，与权限、显卡使用同级入口。弹窗同时展示项目额度、当前目标回合上限和已用量。填写的是调整后的总上限，例如项目已用 40/40，将总上限改为 60 后剩余 20 回合。

项目额度覆盖同项目全部对话，包括手动与自动回合；可修改 1–1000 回合、1–1440 分钟 Agent 时间。Agent 时间保留旧扣账及排除已记录工具区间的既有口径，不是 GPU 训练时间、费用或充值。单回合总历时上限、训练预算和权限不随该设置修改。当前目标上限为 1–40 回合，同时受项目额度约束；尚无持续目标时只显示项目设置，新目标仍默认 8 回合。

## 执行中与阻塞后

运行期间可以保存，两项修改同事务完成。已启动回合的配置、提示词额度和时间上限保持冻结；后续回合读取最新项目和目标额度。正在推进的目标保留执行授权和回执有效性，不因只修改上限而中断。已暂停的目标不自动恢复；额度耗尽的目标在项目及目标两层都足够时变为暂停，点击“继续推进”才继续。上下文等其他阻塞仍由其对应恢复入口处理。

目标卡片在额度不足时提供“额度设置”快捷入口，仍打开相同弹窗。“调整目标”保留研究目标文本编辑，不再重复放置回合上限。已结束或换窗迁出的目标只读，需在接续对话调整当前目标；已归档对话只读。

## 存储与并发

- `GET/PUT /api/v2/conversations/{cid}/budget-settings`。一次 PUT 可只含 project、只含 goal，或同时包含两者。
- `study_budget_revisions` 追加项目预算修订；`budget_changes` 保存请求摘要、来源对话、修改前后值和当时消耗。同项目请求键幂等，重复请求不再修改。
- 项目使用 `budget_revision` CAS，目标使用独立 `limit_revision` CAS；历史目标缺省为 0。目标额度修改不递增运行控制 revision，避免作废在途 checkpoint；旧目标修订 API 改上限时同步增加 limit_revision。
- 目标身份、当前修订、归档状态及已用量在写事务内复核。上限低于已用量、跨对话目标、过期修订均拒绝；两项同时修改时任一失败整体回滚。前端冲突后要求重新读取，不覆盖其他窗口的新配置。
- `formal_studies` 原记录、创建请求幂等摘要、研究 revision、workspace 的 `study.json`/`AGENTS.md` 与历史回合均不重写。原文件是创建快照；当前预算由旁表叠加，每个新回合记录 `study_budget_revision` 并冻结实际限额。
- 关闭或丢失保存响应后可以用相同请求键核对重试；不会产生回合、重置消耗或自动启动模型。
