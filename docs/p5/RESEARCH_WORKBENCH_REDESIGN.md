## 1. 用户目标

研究工作台应让用户直接看清：现在研究哪个问题、推进到了哪里、什么阻碍下一步、当前采用什么方案、经过哪些对话修订、实际运行了哪些实验。成果文件作为这些问题的支撑材料组织。

沿用 design.md 的固定导航、可折叠项目空间、主内容三列框架，以及现有色彩、字号、圆角和留白。工作台主内容内部不再增加常驻侧栏。执行操作台负责对话与指令，研究工作台负责研究状态与证据；两个入口以精确任务、修订、运行及回合引用相互跳转。

## 4. 页面结构

### 4.1 任务上下文

主内容顶端显示任务名称、任务切换入口及最新状态时间。项目名不重复占据大标题，项目空间已有这一信息。

任务切换器分“当前主线 / 其他任务 / 历史研究方向”。查看旧任务只改变浏览位置，不改变当前执行目标，不恢复旧实验。上下文绑定到 task_id；不能因用户浏览旧材料而把下一条指令自动投向旧任务。

当前项目的设计映射示例：

- GIST vs 平滑肌瘤：历史研究方向；归档关系在正式回填前标为“历史关联待核对”，不能擅自改任务状态。
- GIST 危险度三分类：当前对话研究主线；以任务定义和当前会话依据登记正式身份。
- 替代回归/序数方案评估：任务切换的探索材料，不必将每份备选方案都创建为独立已执行任务。

### 4.2 研究阶段与创新分支

病理 MIL 的完整研究导航：数据与任务 → 研究方案 → 执行准备 → 基线实验 → 创新方案 → 创新实验 → 分析与验证 → 论文交付。

这是界面分组，不是所有任务都必须串行走完的固定机器。创新方案可以在基线实验前形成草案，再由基线证据修订；创新实验包含候选开发、对照与消融，分析验证承接稳定性、机制解释和独立确认。仅做基线比较的任务可将创新分支设为不适用，不能为走完流程强行生成创新。阶段支持返回修订和多个子节点并行；不能简单将“当前节点之前的所有阶段”自动涂绿。

各节点分别携带状态：未开始、进行中、待处理、受阻、已完成、需重新检查、不适用、未知。依据事实映射统一 status.ts 色彩。计划改动使依赖检查失效时显示“需重新检查”，旧完成记录仍保留。

点击阶段筛选当前页内容，不触发推进。浏览选中态与实际当前阶段是两个独立状态。

### 4.4 创新方案是独立研究对象

2026-11-01 用户复核指出初版缺少创新方案模块。本修订将其提升为独立视图及显式阶段，不能将创新藏在“研究方案”文件包或最终“分析与验证”之中。参考旧项目 `PerformanceLoopPanel.tsx` 中的假设/反证、候选开发、配对对照、稳定改善、消融解释与独立确认分层；不能直接搬用旧任务的结论。

**页面阅读顺序：研究问题 → 候选比较 → 当前推进方案 → 验证设计与实际证据。**

1. **研究缺口与假设。** 展示基线中观察到的问题及来源；若还只是文献推测或研究者假设，明确标注。说明希望改变哪种能力、为什么现有方法不足、预期可观察现象和什么结果会否定假设。性能提升与机制解释分别表达。
2. **候选池与比较。** 每个候选显示名称、一句话机制、相对基线的改动、来源证据、输入与实现条件、成本估计、未解决问题。支持并排比较、多个方案并行验证、保留与排除理由，不用一个未经解释的总分自动选出“最佳创新”。经典参照与新候选不混为同类创新贡献。
3. **当前推进方案。** 选定方案放在候选池上方或突出卡片中，展示选择者/触发对话、理由、采用修订和后续验证节点。可以有多个并行方案；仅浏览或高亮卡片不等于采纳，更不等于训练批准。未选择时保持“待比较”，没有已关联方案时显示“尚未关联创新方案”，不能假造研究进展。
4. **方法结构。** 用简图指出保留的基线、拟新增/替换模块、输入输出及作用位置；可切换到原基线查看变化。结构图与代码快照是不同证据，草图存在不代表实现完成。
5. **验证设计。** 按问题展示原始基线、完整方法、移除模块、必要的区分对照与其他公平比较条件。每项写清检验哪条假设、配对协议、指标、预先定义的成功/反证条件、矩阵及预算引用，避免只有“做消融”四个字。新增方法或协议改变时触发检查失效与重新冻结规则。
6. **结果与判断。** 方案卡可展开真实运行、跨折/种子稳定性、效应及区间（有证据时）、负向结果、消融解释、独立确认。执行完成、性能达到登记目标、机制假设受到支持、独立确认通过分栏显示；没有结果显示“待验证”，不写预期提升百分比冒充实测。

候选比较维度优先采用可解释事实：对应研究缺口、创新主张与最近相关工作差异、输入兼容性、额外训练成本、实现成熟度、可检验性。文献新颖性需要真实检索与来源，不能根据方法名称或模型意见直接标“创新已证明”。

**修订链：** 一个候选可以有多个 proposal_revision；机制改动、实现修复和再次运行分别登记。多个方案组合时生成明确的组合候选并记录组成关系，不能覆盖父候选。放弃或出现反证的方案继续保留，避免只展示成功方案。局部更改不会自动改变其他候选的采用状态。

**跨视图关联：** 概览出现“当前创新方案/尚未关联”摘要；阶段材料按候选聚合说明、文献、结构图与回执；修订脉络展示为何修改、采纳或放弃；实验运行按 proposal_id + proposal_revision + condition 分组，再展开模型/种子/折。点击证据跳转到具体运行和比较条件，不能将所有创新实验继续压在原七模型 baseline 矩阵下。

**操作：** 从当前研究证据“讨论创新方向”、查看候选、比较方案、提出修订、查看验证设计。明确选型时形成研究决定；启动实验仍经原授权/预算/执行器。已有唯一明确提议的短确认沿用正常上下文规则，不增加重复审批。缺少关键输入时仅澄清影响下一步的选择。

**当前项目与原型边界：** 现有设计快照尚未建立该项目的创新方案关联，原型默认显示空态，不能断言项目绝无相关文件。用户可切换“候选方案布局示例”查看完整布局；示例是假设性界面数据，不是对本病种提出的新方法、推荐或实验结果。切换任务退出示例，防止把布局数据误认为其他任务的已有方案。

## 6. 多轮修订如何直观呈现

用户默认看到“改变的含义”，版本号降为辅助信息。重要修订展示为带因果关系的时间线：

```text
二分类比较研究
  └─ 任务方向调整 → 危险度研究
       ├─ 明确三类任务与患者级划分
       ├─ 冻结数据协议
       ├─ 去除 Mamba、补充 R2T → 七模型比较方案
       ├─ Pilot 异常 → 保留失败并暂停后续矩阵
       └─ 公共路径对齐检查 → MEAN 新报告通过；其余适配继续
```

该图为拟议组织，精确父子关系需用数据和触发回合核实，不能仅靠文件时间补造。

每个节点包括：变更标题、触发用户意图、前后关系、字段变化、受影响阶段/运行、结果证据、来源回合和时间。默认最多展开最近三项，其余按任务/阶段筛选。

必须区分四种操作：

1. **任务切换**：形成新研究问题/任务分支，旧任务及结果保留。
2. **方案修订**：模型、划分、指标、预算等变化；显示字段级前后差异。
3. **实现修复**：代码/执行入口变化，关联代码修订，不自动说科学方案也变了。
4. **运行重试**：保留原失败、预算和尝试编号，不能等同于方案升级。

同一轮对话发布多份材料合成一个研究事件；一轮无实质改变的“查看状态”不新增方案版本。一轮中若发生多个独立决定，可形成多个子事件。跨会话关联依靠 task_id 与明确引用，不依靠时间邻近。

“最新创建”“当前采用”“已批准”“正在运行所用”分别表达。新草案不能自动替换已冻结运行的方案。差异面板展示变化和继承项，输出文件本身保持原样。

## 7. 实时状态与事实来源

状态事实优先从结构化执行回执、任务状态和验证工具读取；Agent 报告可以作为可读摘要，但不能提升为同级运行事实。

每条事实记录 source_type、source_ref、observed_at、覆盖范围和适用 revision。前端摘要区简洁呈现，详情允许查看来源。存在冲突时同时保留并指出待核对字段，不用最新文本覆盖旧执行回执。

区分三个更新通道：

- Agent 回合：处理中、等待工具/权限、回合结束。
- 研究任务/作业：排队、运行、停止、失败、恢复、完成，以作业心跳和持久化回执为准。
- 研究证据：检查通过、指标计算完成、科学审核状态，分别限定适用范围。

推荐使用现有事件传输能力补充研究事件订阅；API 提供带 revision/cursor 的整页一致快照。断线后按游标补齐或重新获取，去重并处理乱序；必要时用可见页面 3–5 秒只读轮询兜底。切换项目/任务时中止旧请求，防止旧数据闪回。

页面标明最后更新时刻；心跳过期显示“最后记录 / 状态待核对”，不保持虚假的“实时运行”。无 epoch 数据不生成百分比；有单元计数也只表达完成单元比例，不冒充剩余时间。失败、取消与成功分开计数。

与 [独立任务代码仓库规划](TASK_CODE_WORKSPACES_PLAN.md) 共用 task_id / code revision / snapshot / run，不额外发明第二套任务系统。该工作当前由其他窗口推进，实施前核对最终接口，避免并发覆盖 api.py、service.py 等正在修改的文件。

扩展发布入口时携带并验证 task_id、stage_id、family_id、parent_revision、run_id 等关系。项目、回合与权限由服务端校验；触发回合尽量由活动工具调用上下文注入，不能由任意文件随意声明。仅有草案的字段不赋予训练授权。

将语义关系保存为增量索引/旁表，原 ArtifactIndex、文件 SHA、源文件及旧成果身份保留。JSON 和 Markdown 仅在同一逻辑版本有显式关系时合包，不能只凭同名确认内容一致。发布失败可以重试登记，不能重复创建研究事件。

## 9. 历史材料接入

既有 76 份产物作为只读输入，先生成可撤销的索引候选：任务归属、阶段、成果族、版本关系、触发回合、依据和置信程度。文件命名可用于候选搜索，不能作为最终采纳/批准事实。

优先使用 JSON 内显式版本关系、方案 change_summary、发布工具回执和实际对话中的产物引用。缺失或冲突的关系标“待核对”，进入“未归类材料”；不能为页面整齐伪造历史。无需让用户逐一确认无争议的文件格式分组，影响当前方案或科学状态的关联才需要核对。

开发者可以实现通用解析器及只读展示索引，但不编辑原研究报告、补写实验结果或将错误结果改正确。Agent 对原研究解释的后续更正作为新的修订节点保存。

聊天删除/归档后的链接应显示来源已归档/不可访问；不得恢复已删除对话内容来凑齐时间线。

## 10. 操作与交互

一个当前节点默认只有一个主要操作，优先解除实际阻碍。未接通执行能力时提供“查看缺口/讨论修复”，不放可点击的“立即训练”。

研究工作台的动作复用任务引导与现有对话工具链：携带 task_id、方案修订、相关材料和 action scope，进入正常回合及预算流程。若当前会话正忙，保留草稿或提示等待，不创建第二次并发派发。旧状态按钮失效并要求重新核对；重复点击幂等。

选择已经明确的下一步可按既有授权推进；不能为每个只读切换或方案查看增加确认。概览与历史中的“打开触发对话”定位到真实回合；“比较修订”只读；“采用方案/启动计算”分别限定语义，不能将推荐或预选视为批准。

详情抽屉承载差异、材料格式与来源；打开时管理焦点，Esc 关闭并恢复焦点。正文至少 14px、元数据至少 12px。窄屏依次呈现任务、当前节点、操作、阶段导航和主内容；八阶段导航使用内部横向滚动并定位当前浏览阶段，避免占满首屏。矩阵可在内部横向滚动，不能撑宽整个页面。

## 11. 分阶段实施

### A. 语义投影与只读工作台

先增加任务/阶段/成果族/修订及创新候选投影和历史候选索引，再替换默认成果平铺页。交付五视图、创新候选比较与方案详情、主要材料、修订对比、来源回合跳转、未知/冲突状态。保留全部文件入口及旧项目兼容。

### B. 执行与实时更新

对接独立任务/运行服务、事件游标、心跳、矩阵和预算。接通前明确未知，接通后验证真实进程状态，不能以模拟数据声称已上线实时训练。

### C. 下一步动作闭环

将工作台操作绑定现有 guidance/对话语义；覆盖任务切换、方案修订、实现修复、重试、运行中浏览历史及多会话情况。由目标 Agent 在隔离任务中验证日常短句与真实工具行为，再用于真实项目。

## 12. 验收要求

- 首屏在五秒内能回答“当前任务、当前节点、阻碍、下一步”，不用翻看全部文件。
- 当前七模型危险度方案与旧二分类方案不会混在同一结果排行中。
- 同一成果的 MD/JSON 以格式呈现；旧版本可找到，但不与当前版本抢占同等空间。
- 能看懂“去除 Mamba、补充 R2T”改变的字段及触发对话，不能只显示 v2→v3。
- 对齐 v1 失败及 v2 后续报告同时保留；局部通过不使整个阶段变为完成。
- 创新方案有独立入口，用户能看懂研究缺口、候选差异、选择理由、方法改动及验证路径；不是又一组文件卡片。
- 无创新关联时不伪造候选或得分；示例始终标明且不进入任务状态。点击浏览方案不等于采纳或批准训练。
- 候选的不同修订、失败、反证及放弃记录可回溯；多个并行方案的实验与消融不会串入基线或其他候选。
- 创新阶段可回退修订或按任务设为不适用；基线尚未完成时允许起草假设，但不包装成已验证贡献。
- 新草案不会替换已采纳方案，也不会改正在运行的代码/协议标签。
- 回合结束、工具成功、检查通过、矩阵完成、科学审核互不替代。
- 断连、旧事件、项目切换、服务重启、重复发布及来源缺失不产生假实时或重复事件。
- 桌面 1440、窄桌面 1024、手机 390 像素，项目栏展开/折叠均可阅读操作；键盘与焦点正常。
- 改版前后核验原研究文件与成果摘要不变；不改预算或原失败记录，不启动旧实验。

本轮交付为设计说明和离线交互原型。正式实现、部署、运行事件接入和模型行为验收分别记录，不能将原型中的交互计为系统执行能力。
