# 任务节点引导与短句推进

发布：0.6.9-p5-guidance。设计依据为 design.md「以推进任务节点为目标的交互」。本次接入明确修改直接推进、关键分岔的结构化选择、成果交付后的下一步，以及选择范围与运行时权限的对应约束。

## 用户交互

- 用户继续使用普通短句，无需字段名或完整提示词。明确的可逆修改沿用现有参数，由研究 Agent 生成、检查、登记新草案。
- 需要决定时，模型通过 `pathoreason_dialogue_offer` 提交一个简短问题和最多三个选项；界面显示动作、说明和范围，并保留“补充或调整”自由输入入口。正文不会被正则解析成按钮。
- 用户点击后直接创建正常研究回合，使用当前模型与思考强度，绑定提议、选项、来源回合和相关成果。不会只把按钮文案填入输入框等待再次发送；未发送草稿保留。
- 自由文字回复携带最近有效结构化提议，供模型按语义判断；系统不把任意“好/继续”硬编码成选择。新回复后旧选项失效；已选择项保留历史，不能重复执行。
- 失败/中断保留现有成果，可从错误处进入已有成果；未知执行结果继续使用既有“核对并恢复”，不自动重放命令。

按钮仅由更新后的模型回合生成；历史长回复不会被补造为已审核的选择。模型不需要决策时可省略引导。草案准备、运行检查和实际训练的完成状态分开。

## 决策范围与执行

| 选项范围 | 点击后的允许行为 |
|---|---|
| clarify / 仅确定方向 | 对话记录选择、提出下一步；禁用文件读取/修改、命令、Skill 与网络探索 |
| inspect / 只读检查 | 读取已授权文件并报告准备状态；禁用命令、文件修改及网络请求 |
| plan / 方案修改与准备 | 按原会话权限完成方案/准备工作；不因此获得真实训练、扩大采集或科学批准 |

前两种范围通过末尾原生 permission 规则收紧当前回合，冻结在 `FormalConfiguration.execution_scope` 中；不会改变用户保存的会话权限设置。下一个普通回合重新应用其实际权限。原生权限仍不是 OS 沙箱；本次没有增加直接训练按钮或绕过原执行器。

## 服务与状态

`conversation_guidance` 保存模型明确提交的提议与选择；`turn_guidance_context` 保存下一回合所绑定的原提议。选择和回合创建在同一 SQLite 事务中完成，沿用模型预算、幂等键、持久派发与未知结果核对机制。预算失败/事务回退不消耗选项；重复点击不会启动第二个回合。

提议绑定当前会话、源回合、项目 revision 和成果索引摘要；新回复或成果变化使未选择的旧提议失效。点击前校验登记文件和相关工作区源文件的 SHA。源文件变化时拒绝旧选择；自由文字纠正仍可继续，不强行绑定失效提议。当前成果索引摘要为项目级，其他会话新增成果也可能保守地使旧选项失效，后续可按依赖粒度细化。

原生 MCP 使用独立私有 `guidance-token` 和本回合能力凭证，内部端点校验身份、活动回合与正式项目。公开响应不含凭证，模型输出中的当前凭证会被隐藏。删除会话时清理提议和跟进上下文，保留原回合预算。现有正式项目无需迁移研究文件；旧配置的 execution_scope 默认 standard。

契约增量：TurnInput 可选 guidance_selection、TurnView 可选 guidance；旧请求未传新字段时保留既有请求摘要。新增快照为 contracts/api-p5-guidance.openapi.json 和 contracts/p5-guidance，旧契约快照不覆盖。

## 验收与边界

证据：`/data/bxn/PathoReason/acceptance/task-guidance-20261031`。独立合成项目 `prj_6ba34c7d83564f18b079b3c7648d5de8`，12 回合/1200 秒；上一轮验收账本不重置。模型为 OpenCode 1.18.33 + DeepSeek Flash/high；输入合成，真实模型输出原样保留。工程工具审批、失败和中断均计入证据，等待审批的墙钟不能用作模型延迟比较。

初版点击“仅记录方向”后，模型尝试写方案，开发者未批准该写入并停止测试回合。该失败推动加入运行时范围限制；不删除失败或修改模型输出来计为通过。修复后的方向选择仅调用一次引导工具，未读写文件，并给出后续起草入口。后续实际结果见同目录 JSON 记录。

仅澄清与只读检查的能力约束、按钮与文字续接是平台能力；科学判断和研究文案仍由模型负责。本次合成比较不能作为真实临床数据、模型适配、训练、统计稳定性或论文结论的验证。

### 本轮结果

工程回归 213 通过、1 跳过；前端 TypeScript 与生产构建通过。浏览器 1440/390/320px 验证按钮直接提交、重复点击只建一回合、保留输入草稿、键盘自由输入、旧选择失效、刷新不重放和无横向溢出；另有真实前端点击与服务端回执。详情见 browser-results.json、live-choice-*-receipt.json 与 results.json。

| 实际输入/动作 | 结果 |
|---|---|
| 留出法还是交叉验证，先别改 | 一次引导工具给出两个选择，无探索 |
| 多选之后“那按你说的来” | 复用原来两个选项，一次引导工具，无擅自选择 |
| 初版点击“仅记录方向” | 模型尝试写方案，未批准写入，回合中断；保留失败 |
| 修复后重新提出两个选项 | 一次引导工具，无探索 |
| 修复后点击留出法方向 | dialogue 权限下只记录选择并给出起草入口，一次引导工具 |
| 点击起草 v2 留出草案 | Agent 自行生成、检查、登记 v2，6 fits；16 次工具调用 |

| 点击“先查执行就绪” | inspection 权限下完成输入/划分/适配器检查，仅 read/glob/grep，共 19 次调用，无计算或文件修改 |

实际使用 9/12 回合、1090.493958/1200 秒，包含中断和工具审批等待；不补写成功、不重置旧预算。剩余预算保留，更多数据、唯一提议后的短确认、冻结划分变更本轮未补验。工程操作者逐次批准了夹具读取、可信校验/登记 helper，以及只读检查所需的隔离研究目录与旧引擎源码访问；不是无人干预验收，也不能用总墙钟比较模型速度。

原 GIST 研究项目 1701 个文件 SHA 完全一致，未调用其会话；合成输入原始文件 SHA 亦未变化。模型自主产物保持原样：v2/v3 主方案已登记；v2 变更说明位于 plans，模型尝试登记时被既有 outputs 目录规则拒绝，回答如实说明失败，开发者未代修该成果。

剩余问题：只读检查仍有过多探索/外部目录授权，回答仍偏长且包含技术细节；部分选项文字与范围不够一致，相关成果引用可能仍指旧版本。当前运行时收紧覆盖显式按钮的 clarify/inspect；自由文字按模型语义处理，不能宣称获得同等机器级范围推断。plan 沿用原会话工具设置，仍可能需要命令授权。未增加通用执行按钮、自动训练或扩大数据范围的权限。推荐下一步的文案质量仍需要持续验收；本次没有通过改写模型回答掩盖这些限制。
