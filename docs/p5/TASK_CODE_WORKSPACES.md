## 当前交付

第一阶段已实现并部署，独立合成项目已有真实 Agent 创建、修订和冻结回执。`TaskWorkspaces` 复用应用 Store 和事务，采用增量旁表，不修改原项目、对话、回合、业务预算或成果记录。`TaskCodeService` 从当前活动正式回合绑定项目、对话、运行配置与 Agent 来源，检查回合 grant、冻结配置摘要和只读/澄清范围。`scripts/task_code.py` 是可调用 JSON 工具，内部 HTTP 入口使用现有私有桥接凭据；没有允许公开 HTTP 直接派发研究的接口。

- `create` 从明确版本模板及文件 SHA 清单创建任务独立 Git，不复制研究空间或共享可写源码。来源保存公共提交、上游逐文件摘要/许可证、模型与配置契约、依赖声明和验证范围。父任务必须属于当前项目。
- `revise` 登记 Agent 自己提交的 clean Git commit 与全部字节；任务级 expected_revision 和项目锁拒绝并发覆盖，原修订保留。禁止重写已登记 Git 祖先，拒绝外链、子模块、Git include/filter 等配置。
- 操作 key 具有持久幂等语义。失败回执和事件保留，不自动重派 pending/failed 动作。创建失败不登记成功；已经发布到磁盘但数据库登记失败的孤立副本保留待核对，不清理研究材料。
- `task.json` 只是投影，不能改变权威修订或获取训练授权。状态、检查和快照登记均在应用数据库旁表。
- `inspect_update` 返回模板文件差异及任务对应摘要，保持任务代码与运行材料不变。更新由研究 Agent 应用到新 commit/revision。

第二阶段**仅完成源码结构检查与内容绑定快照部分**。`check` 检查干净 Git、真实文件与 Git blob 一致、Python 语法和明确依赖版本声明；不运行任意任务代码。`freeze` 绑定检查、修订、全部源码字节与模板来源，复制前后重复验证，独占构建并设只读权限。`verify_snapshot` 按数据库登记重验全部源码，拒绝篡改。未跟踪及 ignored 文件都阻止冻结，避免遗漏执行依赖。

这些结果明确使用 `scope=source_structure_only` / `scope=source_only`，`execution_ready=false`。不是完整执行快照或科学审核。`launch` 首先核对快照，再返回 `execution_backend_not_ready:immutable_environment_and_authorized_controller_required`；不会从任务工作目录直接起进程。

第三阶段提供 `task-code-workspaces` Skill、发布模板目录和当前正式回合动态提示，已完成下述部分真实行为验收。完整运行失败后的恢复/重试和界面进度展示尚未完成；未修改界面。
