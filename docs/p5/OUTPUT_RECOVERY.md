# 输出截断、未知阻塞与准备恢复

2026-11-02—03，发布 `0.6.18-p5-output-recovery`。修复提交 `b6e70f9`、`dc94e56`。证据：`/data/bxn/PathoReason/acceptance/output-truncation-20261102/`。

## 真实失败与责任层

原研究项目的 `conv_1caef475f8b64910b6b7dc73be447f06` 沿用了只读验证权限。用户请求继续基线适配、暂不训练后，DeepSeek Pro/high 连续三次返回 `finish=length`：单次 8192 token 全用于思考，公开输出为零。旧适配层仅看 completed 时间，误记 completed；目标引擎按缺检查点重试，两次无进展后停下。用户手动恢复后又发生截断并自动续行第四轮。无结构化 blocker 的目标说明默认折叠，用户只能看到“遇到阻塞”。

开发者通过公共 pause 控制停止空转并中断第四轮，保留原始输出、失败状态、计费、冻结配置及人工干预回执。前三轮的历史 completed 误分类不回写。诊断与修复不是替研究 Agent 改报告或结论。

## 公共机制修复

- 原生最终 `finish=length` 映射为 `runtime_output_limit`；仅思考、无公开文字或工具结果的正常结束映射为 `runtime_empty_response`。保留已有公开部分和原始 token 计量，不暴露 reasoning。先等原生 idle，再结束应用回合；较早步骤或别的 parent 的 length 不污染后续正常结果。
- 截断回合记 failed，目标立即阻塞，不再自动重试或假作完成。工具执行成功且已有检查点的无文字回合仍合法。
- 所有 blocked/额度耗尽目标展开说明；错误文字指出真正原因。输出截断后可显式“低思考强度重试”；低强度仍截断时可显式“关闭思考重试”。配置来自服务端能力目录，恢复操作只改后续请求模板并追加目标事件，不改模型、权限、输出上限、项目预算或旧配置。未操作按钮不会自动降低强度或重试。
- 纠正公共提示中的错误依赖：训练后端缺口只阻塞需要启动训练的目标；独立适配、合成检查和源码冻结不依赖该后端。准备工具被 deny 时使用 permission blocker，后续训练缺口另行说明。

新 GoalControl/GoalView 可选字段及 API 快照保存在 `contracts/p5-output-recovery/`；旧契约快照保留。

## 分层验证

**工程：**完整回归 377 通过、2 跳过；补充关闭思考与准备边界后定向 54 项通过（有重叠，不相加）。TypeScript/Vite 构建通过。三宽度显式 UI 夹具验证原因自动展开、low/none 请求以及旧式无 blocker 的阻塞；写请求本地拦截，不派发真实任务。最初两项测试因隔离数据目录未创建而失败，原日志保留，补齐测试目录后复验通过。

**原生：**把三条真实历史 length 消息送入新适配器，只读回放均判为 runtime_output_limit。另启动独立 OpenCode、假凭据和 loopback 模型端点，实际捕获 low 与 none 请求的 `reasoning_effort` 正确且 `max_tokens=8192`；无外部模型调用。该检查排除了参数丢失，不能证明 low 必定避免截断。原生正式 OpenCode PID 380742 未重启，仅应用和静态资源更新。

**真实模型：**同一目标、同一 DeepSeek Pro、同一只读权限、同一预算，共 3 回合：

1. low 仍用满 8192 思考 token、公开输出零；新机制正确 failed/blocked，无自动接续。保留失败，不能算恢复成功。
2. none 返回公开回复并成功提交检查点，但把 preparation-only 目标错误标为 training_execution 阻塞。修复公共目标与任务提示。
3. 经正常 revise 控制重新提交完全相同的目标文本，再以 none 恢复；没有扩大范围、改目标上限或手写 checkpoint。Agent 自行纠正为 permission blocker，不再把训练后端设为恢复准备的条件。恢复过程中只有 checkpoint 工具调用，无命令、文件写入或训练。

后两轮仍带有较多过程性文字；原文不裁剪成“成功样例”。none 的有效性仅在本次状态恢复得到验证，不代表适合所有科学任务。官方参数含义参考 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 与 [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)；模型实际行为以本次原生回执为准。

**科学：未通过。** 最后 checkpoint 的 next_action 仍继承了“重划分后新台账 exposure=0”错误，尽管公共规则已明确历史暴露不可清零。没有改写原输出，也没有执行该计划。需要研究 Agent 在保留累计暴露、禁止冒充独立盲测的边界下重新核对方案；不能把权限/阻塞恢复成功当科学验证通过。暂不建议按这条 next_action 直接放开执行。

3970 个既有研究/工件文件的大小和修改时间不变，原记录有 SHA 的文件哈希亦不变。数据库既有行中只有当前 research_goals 状态经正常公共接口更新；旧回合、配置、成果、额度及事件保留。新增事件可追溯暂停、低强度恢复、关闭思考恢复及相同目标的重新核对。原生原始消息与完整配置副本权限 0600，不进入源码。

前端刷新后当前应显示“工具权限不足”，并保留“继续推进”入口。该对话仍为 bash/edit/webfetch/external_directory=deny；没有静默放开权限。下一有效节点是先在只读条件下纠正暴露归零建议，再由用户决定准备工具权限与后续额度。若允许执行准备命令，依旧不允许启动真实训练、绕过执行器或重置测试暴露。训练执行器、不可变环境、硬预算和测试隔离仍为后续工程缺口。

发布包保存源代码、静态资源及 SHA。恢复应采用同一版本包或保留新增字段解析能力的修复版本，不能直接把数据库回滚到旧快照来清除失败或消耗。
