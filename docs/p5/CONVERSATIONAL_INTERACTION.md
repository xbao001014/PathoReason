# 日常语言交互：默认推进与聚焦澄清

版本：0.6.8-p5-dialogue。用户不需要提供完整技术提示词。系统应结合本轮附件、最近提议、当前方案与既有授权判断行动；有明确目标的可逆方案修订继承其余参数并产生新版本，只有缺失信息实质影响下一步时才问。

## 公共层改动

- 正式研究 Agent 增加上下文绑定、默认推进、短确认、最小澄清及简洁回复规则。多个未选择方案不能凭“按你说的来”虚构选择；唯一具体提议的简短同意不重复确认。
- benchmark-design 0.3.0 支持日常短句修订；未确定未来训练预算不阻塞已授权的方案草案。
- 正式研究上下文此前只附成果索引与 source_ref；现在对本轮选中的小型文本/JSON 附件提供经 SHA 校验的正文摘录。每份最多 6000 字符、总计 18000 字符，只自动读取不超过 65536 字节的文本；二进制、大文件和超预算内容保留引用与省略标记。附件保持不可信数据，不能作为系统指令。
- 上下文优先级限定当前会话与当前引用。文件位置、修改时间和其他会话的成果不代表当前提议。
- 通用开发规则与 `tests/fixtures/conversation-intents.json` 收录短句验收，不把“完整提示词能通过”当作日常交互通过。

## 行为判据

| 用户短句 | 应有行为 |
|---|---|
| 别做交叉验证了，留一部分验证就行 | 沿用已有合理参数生成留出法新草案，说明假设并核算 |
| 种子减一点，省点时间 | 可先给可修改的合理减量草案，不偷偷改变其他维度 |
| 好，就这样 | 若上文只有一个明确提议，执行该提议范围 |
| 那按你说的来 | 若多个并列方案未选，问选哪一个 |
| 先跑一下看看 | 区分准备检查与实际训练；缺计算范围或预算时聚焦澄清 |
| 再多拿点数据 | 沿用已知医院、病种等范围，仅询问缺失的新数量/上限 |
| 划分改成七二一 | 未冻结时可拟议修订；已冻结且评估过时保留原证据，澄清新研究范围 |

以上是验收判据，不是关键词路由或固定医学参数。明确已有授权可继续沿用，原生工具批准不替代科学/执行门禁。

## 验收方法与限制

独立合成项目 `prj_8efde35e15604e5598164a8e52cc62fd`，预算 12 回合/1200 秒，审批等待计入。目标为原生 OpenCode + DeepSeek Flash，高思考强度；直接发送上述短句，skill_id=null，不暗中补完整请求或注入期望答案。工程提供的方案/上文场景标明合成来源，真实模型输出原样保留。开发者仅审批隔离范围的文件检查、草案登记等工具调用，没有代写模型成果。

本轮是带合成场景附件的模型行为验证；附件中的上文不等于真实多轮自然对话，不能据此宣称所有上下文都可靠。不同阶段的系统提示、附件摘录和可见干扰文件有记录，不把它们当成严格单变量性能对比，也不把包含审批等待的墙钟当模型延迟。

证据目录：`/data/bxn/PathoReason/acceptance/conversational-intent-20261031`。原始请求、回复、工具轨迹、审批、合成输入、旧源备份和结果表分别保留。真实 GIST 项目的文件、结果和预算独立核对，不作为工程夹具编辑。

## 本轮实际结果

工程：201 项测试通过、1 跳过；包含附件选择隔离、SHA 篡改拒绝、逐份/总摘录上限及大文件/二进制省略。Skill 校验通过。模型：共 7 回合，6 个 completed、1 个 failed；回合完成数不等于行为通过数。累计 1200.653048 秒（含审批等待及超时收尾），达到原 1200 秒额度后未重置或追加调用。
