# 上下文阻塞恢复

服务器版本 `0.6.14-p5-context-recovery`。本次修复来自真实会话的 `context_window_requires_compaction_or_handoff`：目标自动接续有效，但高占用时卡片只显示旧进展，普通继续会再次失败，压缩成功后的占用仍读取旧研究回合。

## 交互与语义

上下文阻塞时目标卡片自动展开，直接说明原因；普通“继续推进”替换为“压缩并继续”和“同项目换窗并继续”。压缩会调用模型，后果在按钮旁说明。未知压缩只提供“核对压缩并继续”，不盲重发。压缩次数用完仍可同项目换窗；结果未知且原生仍忙时两条恢复路径都会被服务端拦截。旧目标的进展和验收条件保留。

换窗使用同一个项目和目标 ID，保持已用回合、目标上限、项目预算、验收条件、证据与授权来源；复制当前明确保存的工具策略/GPU 绑定，自动轮继续继承原执行范围。原生 session 的临时逐项 always 授权不复制。旧对话留下接续入口，历史保留；新会话带有有界的近期对话来源和目标状态，不能重放完成的训练或测试。迁移后的目标及其上下文属于新会话，删除旧对话不等于取消新会话目标。

控制请求绑定源会话、目标 ID 和目标版本；重复点击返回既有结果。创建新会话、迁移目标、设置和回执在同一事务内完成。暂停、取消、归档或修改目标优先于压缩结束后的自动恢复。重启遇到未完成的恢复意图时标为待核对，不重发摘要或模型任务。恢复动作本身不清零任何预算；后续正常模型回合仍经过项目预算、权限和上下文检查。

## 压缩核验

成功原生摘要必须包含正确的父 compaction 消息、完成标记、无错误和可解析的保留 tail。实现参考服务器安装的 OpenCode 1.18.33 `filterCompacted`：保留 compaction 请求、摘要、tail_start_id 指定的尾部及之后消息。平台对整个保留 JSON 的 UTF-8 字节计数并加预留，标为 `post_compaction_bytes_estimate`；这是保守工程估计，不是供应商 token 计费或精确 tokenizer 结果。未知结构不清零占用，也不放行。

压缩占用存在独立 `context_projections` 旁表，绑定原生 session、压缩操作和原最后回合；不覆盖历史 usage。下一研究回合自动回到该回合的原生用量。摘要输入 tokens 衡量压缩前历史，不能作为压缩后的占用。压缩响应遗失时按原生摘要标识核对并补投影，不再调用一次摘要。

正式项目压缩额度按项目累计，默认最多 2 次，失败和未知结果都占次数；同项目换窗不重置。旧非正式环境额度仍保留原口径。压缩操作账本与研究回合预算分别展示，不把未知费用写成零。发送前的研究附件估计改为计算实际注入的有界摘录和元数据，不再用不会完整注入的大文件大小累加。
