# 公共训练执行与独立训练预算

2026-11-03，目标发布 `0.6.21-p5-training-executor`。证据目录：`/data/bxn/PathoReason/acceptance/training-executor-20261103/`。最终发布和模型验收记录见本文后续追加。

## 用户节点

给定数据集并选好基线后，Agent 负责适配、内部检查、依赖准备、源码冻结与实验登记。仅遇到会改变协议、数据边界或资源范围的取舍时澄清。不要求用户逐步确认 Git、冻结或合成验收。

正式启动前，在对话下方独立的“训练 / 确认训练方案”入口核对实验矩阵、评估范围、计算设备、内存和训练预算，一次点击“按此方案开始训练”。该决定直接启动后台控制器；无需再发“继续”，无需消耗一个模型回合才能启动。

| 设置 | 归属与扣账 | 到达上限 |
|---|---|---|
| 项目回合、Agent 时间；目标回合 | 原项目/目标 Agent 额度；保留所有旧消耗 | 停止新的模型推进；已授权后台训练继续 |
| 累计执行时长 | 单个实验所有单元的实际执行秒数，包括失败与重试 | 停止当前单元，保留日志、checkpoint 和账本 |
| 累计 GPU 时长 | GPU 单元占用秒数；当前实现串行、每次一张 GPU | 与累计时长中更早耗尽者共同限制 |
| 单元最长时间、每单元最多重试次数 | 同实验跨修复、跨启动累计；次数含失败和未知尝试 | 停止后由用户决定是否增加上限 |

GPU 排队和准备环境不计训练执行时间。单元计时包含输入/产物校验、进程初始化及运行；不是 GPU 利用率积分。GPU 秒与执行秒是两个同时约束的上限，不是两份可相加的余额。当前不计币种/云账单，也不支持多卡并行。

预算表单填写**累计总上限**。保存保留消耗，不会自动恢复已停止的实验；随后点击“继续训练”。运行中新增额度供后续尝试使用，当前单元的起始期限不会被无限延长。用户停止和取消优先；权限“自动批准”不会自动批准训练预算。没有有效预算/方案决定时不能启动，Agent 工具也不能设置授权或增加额度。

## 公共机制

- `training_contracts.py` 定义通用 Python 单元、输入文件、依赖产物、资源与预算；不限定任务类型、模型名、种子/折数或病理数据格式。Agent 在自己的任务仓库适配入口，平台不替写研究脚本或结论。
- `training_files.py` 复制并哈希配置目录内的 Python、stdlib、site-packages 和项目依赖，形成不可变环境。入口用 `-I -S -B`，显式受控搜索路径，禁用宿主 site 初始化。requirements.lock 精确版本必须与冻结环境实际元数据一致；环境 ID 绑定实际文件。宿主内核、libc、驱动仍属于平台边界，不能称为完整 OS 镜像或跨机器可复现证明。
- `training_service.py` 对模型入口核对当前回合、grant、冻结配置、选择范围和项目；长环境复制不占全局交互锁，晚到结果重新核对回合。模型可 prepare / inspect / launch / stop / retry，不能 approve。用户决定采用实验修订 CAS 与幂等键，存量预算和计划历史不重写。
- 科学范围（数据、矩阵、参数、协议、GPU/内存）变化必须重新审阅；范围不变的代码/依赖修复可沿用原批准与预算。不同科学范围的已完成单元不能误作新矩阵完成。完成输出逐文件哈希，后续单元只能读取显式 depends_on 的已完成产物，校验前后字节并只读传递。
- `training_worker.py` 是独立进程，冻结控制器副本、配置、环境、源码、输入清单和起始预算，后台串行调度。浏览器关闭、服务重启、模型额度耗尽不杀训练；原生 Agent 不承担轮询。GPU UUID 校验、空闲检查与平台互斥锁约束本执行器任务。
- `training_account.py` 追加实验计划、用户预算修改、尝试、失败、曝光与控制器事件。SQLite 事务确保单次派发。未知控制器结果先撤销派发，保守保留完整预留消耗，不重放；用户核对后显式重试会创建新尝试。
- 操作系统隔离复用原引擎 Landlock/seccomp：任务只读冻结源码和受控输入，仅可写本次输出；拒绝网络、子进程及平台账本访问。systemd 用户 scope 限制内存、任务数及墙钟，父进程死亡绑定清理工作进程；GPU 模式另要求私有网络命名空间与指定设备。
- 目标与训练额度分离：用户批准后将对应准备目标绑定到训练回执；完成/可修复失败自动进入下一模型节点，仍受原 Agent 与目标额度约束。暂停/取消目标不恢复它，也不等同停止训练。额度耗尽/未知/用户停止通过“训练设置”处理。

## 科学边界与来源

来源配置：`config/p5/training-executor-provenance.json`。`training_restrictions.py` 是旧仓库隔离模块的逐字复制；原文件不改。复用隔离和父进程/资源控制机制，而不把新任务硬塞进旧固定工作流 CycleLedger。旧训练账本和计算标志保持；新平台执行器有自己的明确实验授权、预算、输入边界与记录，不能从通用 bash 绕过它。

训练单元禁止收到 sealed 输入。评估必须等所有 fit 完成，暴露在派发前记录（失败也保留）。内容 SHA 与 subject 身份绑定，已知曝光不能降低，未知不能改成零，已封存 subject 不能直接改作 development。初次来源/既有数据暴露仍需 Agent 如实声明并接受科学核查；机械账本不能识别所有语义伪造，也不能把重划分变成“全新独立盲测”。同一批准矩阵中的计划评估保留逐单元曝光，不能用此机制申请反复调参与再测。

`completed` 仅说明进程、要求的产物及字节检查完成，`scientific_approval=false`。数据适用性、指标含义、统计有效性、独立科学审核和作者门禁保持独立。不修改原研究报告中的旧错误来凑验收。

支持范围为 Linux、可用 Landlock/seccomp/systemd 用户服务、Python 单进程和线程。需要多进程 DataLoader、DDP、网络下载或外部命令的任务必须由 Agent 在获准范围内适配，不能放宽隔离绕过失败。GPU 真实训练须单独验证，CPU 合成通过不代表 GPU 已验收。

## 发布与回退

新表为增量创建，原项目、回合、消耗、配置和研究文件保持。构建保留主分支已有样式；更新前核对活动回合、目标和原生进程，保留数据库与源码/静态包 SHA。仅空闲时停 app，refresh-native 重新加载 training-execution Skill、MCP schema 和超时设置，保留 OpenCode 进程和原会话。

回退不能恢复旧数据库来抹掉消耗。后台执行使用启动时冻结控制器，回退 app 代码不会停止它；恢复到能读新表的修复版，显式检查/停止对应实验。保留新账本、失败、环境与输出，不删除证据以换取重试。

发布前最终工程：完整回归 `404 passed, 3 skipped`（`full2.txt`）；随后补充当前 grant/只读选择范围验证与 MCP 回归 `2 passed`（`authority.txt`）。PyTorch 专项单独执行通过，不把全量中有意跳过的 GPU/外部运行环境称作已验收。TypeScript/Vite 最终构建通过；三宽度最终界面脚本在等待按钮解除 busy 后全部通过（第一次复跑过早点击禁用按钮的夹具超时保留在 `browser-final.log`，不是线上训练失败）。
