# 已有成果进入独立阶段对话

2026-11-04，版本 0.6.31-p5-stage-entry。用户指出当前 GIST 会话以创新实验为主，要求新建对话进入稿件部分。根因：早期五阶段接入将稿件阶段直接关联到旧混合会话；普通“＋”不迁移项目阶段所有权，而阶段 switch 只服务下一阶段，无法让已经关联稿件的旧会话迁入独立稿件窗口。

## 交互

在当前会话标题栏打开阶段浮层，点击“新建稿件对话并交接”。同项目创建 `5/5 · 稿件部分` 并自动跳转。旧对话保留；新对话显示接收的交接内容、成果引用和稿件五个作者节点。新建本身不调用模型、不启动训练；用户在新窗口输入稿件任务后才执行。

这是所有阶段通用的已结束任务换窗能力；其他阶段显示“新建本阶段对话并交接”。仍在执行/等待/暂停中的目标不能借此重开目标额度，上下文阻塞继续使用已有目标恢复入口。已经 ready 的阶段继续使用“切换并继续”正常进入下一阶段。当前作者审核待处理时不允许迁移，避免审核包与目标脱离。

当前 GIST 有完整初稿、图件、补充、文献库和作者待办，先复用这些材料准备事实/写作方案审核；不额外要求研究正结果，不把历史交付当独立科学批准或作者批准。

## 机制

- `POST /api/v2/conversations/{cid}/stage/new-conversation` 使用 `StageSwitch.expected_revision`；CAS 与 `(source_conversation,revision)` 唯一记录使双击/重试只创建一次。
- 要求当前阶段会话、可写项目、已结束目标、无待审作者包、无运行/未知训练或模型回合、无未解决上下文/原生权限操作。
- 校验已有 handoff 摘要、成果字节与版本；没有历史 handoff 时使用目标已核验的证据和摘要。内容变化拒绝交接，不能复制过期成果。
- 新 `research-stage-entry/1` 包保存来源、原目标、结果摘要、局限、未决问题和成果引用，标明摘要不是批准。`research_stage_relocations` 保存项目内交接记录；新阶段上下文从此记录取包。
- 同一项目、同一 workspace、相同权限/GPU 设置，新会话尚无 native session。旧目标、冻结配置、历史回合及消耗保持；不把已完成旧目标改为 active，也不自动给新窗口发请求。后续用户任务在正常调度器下创建新目标，受原项目剩余额度限制。
- 保留旧阶段交付到历史，项目当前阶段关联切到新窗口，既有作者事实/批准仍归属于同项目；不回填任何审核或科学状态。项目删除沿用明确资产清理授权并清理关联记录。
