# 直接答复并确认写作方案

2026-11-04，0.6.32-p5-review-efficient。真实问题：当前 blueprint 的 author_questions 非空，前端 !questions.length 与后端无条件拒绝叠加，用户填入意见后仍无法确认。只能 clarify、等模型重新登记、再批准，造成不必要的往返。

## 动作与边界

方案节点有问题时，主操作明确为“提交答复并确认方案”，非空答复后可用。用户点击携带 approve、confirm_answers=true 与原文 comment。后端只允许 blueprint 的待答问题使用组合动作，校验原材料/快照/上游链、CAS revision、原生空闲与权限后，一次保存答复和批准并进入 draft。receipt.question_response 包含原问题列表、用户原文和 confirmed_with_plan，原审核材料和原问题不改写。批准的是写作方案与作者答复，不表示事实已被独立验证、科学内容冻结或投稿授权。

不自动解释任意文本为批准；普通继续仍定位审核，主对话详细反馈仍走 clarify。自由文字是否真正解决每个语义问题仍需 Agent 结合证据处理；若答复改变已审范围或冲突，必须提出具体差异，不能猜填事实。按钮明确表达用户将答复与方案一起确认。

修改意见直接通过“按意见修改”提交 revise，不批准方案；反馈无必需的重复确认。后续 draft/review/scientific/delivery 中缺少必要事实时仍先修订材料，再审阅确切版本。完整性阻塞、被修改的材料、逐条裁定和后两节点显式内容确认不能由组合动作绕过。暂停/额度耗尽/已完成目标原有行为保持；不扩大训练预算或权限。

confirm_answers 默认为 false；计算命令摘要时省略 false 字段，保证历史版本的幂等请求仍可重试。原请求与回执全部保留。契约新增快照 api-p5-review-efficient.openapi.json 与 p5-review-efficient；旧快照不覆盖。模型 checkpoint 不增加作者批准工具。

## 呈现与 Agent 指导

正文顺序为当前节点、确认后动作、必要问题、答复输入、确认/修改两个操作，随后才是审核材料、核对记录和详细说明。方案材料默认折叠，后续稿件材料默认展开。按钮禁用时明确原因，避免只显示不能点击。阶段浮层仍保留稿件阶段、研究五阶段与上下文交接。

公共稿件提示要求用通俗语言先说已完成什么、推荐何种选择、批准后做什么；技术清单放材料。复用已确认事实，不重复询问。可选未来方向作为非阻塞说明，不要求用户承诺新实验。组合批准中的原文答复进入后续上下文，Agent 应据此生成初稿，不再询问相同方向。此更新进入未来回合提示，没有人工改写当前研究请求、稿件或结论；不宣称真实基模已验证这些新指导。
